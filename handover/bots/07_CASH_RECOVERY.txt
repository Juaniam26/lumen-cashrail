BOT PACKET — REVENUE LEAKAGE REVIEW / HISTORICAL L7
Canonical policy: config/revenue-runtime.json

ACTIVE PRODUCT — STALLED PROPOSAL RECOVERY (L7B)
Help B2B clients re-engage proposals/quotes they already sent before Cashrail arrived. The client owns the customer relationship, checkout/invoice path, and customer payment. Cashrail runs the recovery board, research, follow-up drafting, and approved workflow.

PAUSED PRODUCT — THIRD-PARTY INVOICE COLLECTION (L7A)
DO NOT OPERATE THIS PRODUCT.
Third-party past-due invoice collection is paused for compliance and payment-provider design. Do not prospect it, sign it, send collection messages, or treat the old contingency language as current authorization.

L7B IDEAL CLIENT
B2B service businesses with a real backlog of open proposals/quotes and a credible ability to provide:
- proposal/account name
- amount
- date sent
- last customer response
- current status
- proof the proposal predates Cashrail

OFFER
Cashrail rebuilds the follow-up board and creates/runs the approved re-engagement workflow. Compensation may be a negotiated percentage of attributable first payments on already-existing proposals that close inside a defined attribution window.

PAYMENT PATH
customer -> client's existing checkout/invoice/payment path -> client receives cleared funds -> client pays Cashrail agreed attribution fee

Cashrail does not receive customer settlement and pass it to the client.

SOURCE / TARGET EVIDENCE
Prospecting claims require public/provider-authorized evidence with URL/record id + retrieved_at + observed fact. No live evidence = BLOCKED_NO_LIVE_SOURCE.

FIRST-TOUCH FRAME
Subject: Those quotes are still an asset.

You already paid to create the opportunity and send the proposal. If a real batch is sitting open, we can rebuild the follow-up board around those existing quotes and get paid only on attributable first payments that actually land.

You keep the customer relationship and payment path. Start with a redacted list: account, amount, date sent, last reply.

FOLLOW-UP BOARD
proposal_id | account | original_amount | date_sent | last_reply | client-approved contact route | next action | evidence/status | attributed payment id if closed

WORKFLOW
1. Confirm proposal existed before engagement.
2. Confirm client authorizes the contact path and message policy.
3. Draft/research without inventing customer facts.
4. Dispatch only through an authorized provider/workflow.
5. Store provider message/status evidence.
6. Stop/suppress when requested.
7. If closed, bind the client's verified first-payment evidence to the original proposal before calculating fee.

FUNNEL
eligible proposals -> approved contact route -> provider accepted -> delivered -> replied -> requalified -> signed/closed -> first payment verified

KILL / REPAIR
- client cannot prove proposal existed -> kill
- customer asks to stop -> suppress thread
- client asks for threats/impersonation -> kill
- replies but no requalification -> inspect proposal age/fit and message
- requalified but no close -> inspect commercial terms/decision blocker
- claimed close but no payment evidence -> payment remains unverified

HARD BOUNDARY
No consumer debt collection. No third-party invoice collection while L7A is paused. No fake legal escalation. No hacked inboxes or leaked data.

DONE
An already-existing B2B proposal is reactivated through an evidenced workflow and an attributable first payment is externally verified. Net contribution, not nominal proposal value, determines economics.
