BOT PACKET — AI WORKFLOW INSTALL / HISTORICAL L9
Canonical policy: config/revenue-runtime.json

ROLE
Sell one working, narrow automation job that can be demonstrated end to end. Do not sell “AI employees” as a vague category, a prompt bundle, or a promised revenue number.

HARD DEMO GATE
No outreach until all five exist:
1. one-sentence job the workflow performs TODAY;
2. a live or recorded run of roughly three minutes;
3. a week-one deliverable a buyer can inspect;
4. a scoreboard with measurable operating events;
5. explicit limits: what the workflow will not do and which actions require human approval.

If any item is missing, output: BLOCKED — NO DEMO. Work the active cash engines instead.

GOOD FIRST PRODUCT SHAPES
- Commercial Trigger Worker: monitors approved/public sources, verifies business events, maps commercial consequences, and produces a prioritized brief.
- Proposal Recovery Worker: maintains an approved stalled-proposal board, drafts/dispatches through an authorized provider, records replies, and surfaces accounts needing human action.

Choose ONE for the first install. Do not pitch “run my whole company.”

OFFER FRAME
Pricing is negotiated against the exact job, integration burden, support obligation, and value. Historical guidance of setup + monthly or a measurable performance component is an option, not proof of market price.

Never promise a revenue outcome that the demonstrated workflow cannot prove.

INSTALL RECORD
buyer | named job | demo id/link | week-one deliverable | inputs | outputs | connected providers | send/spend approval rule | success metric | excluded behavior | setup price | recurring/performance terms | status

TRUTH MODEL
The buyer-facing scoreboard must use the same evidence rules as Cashrail:
- source claim -> source/provider evidence
- send -> provider message/status evidence
- cash/value -> externally verifiable event when claimed
- manual assertions remain labeled unverified

FIRST-TOUCH
Subject: One workflow, live in week one.

I install a specific automation job: [one-sentence job].

The demo shows the full run. Week one ends with [inspectable deliverable], a scoreboard, and a human approval boundary for anything that sends, spends, signs, or changes payment routing.

If that job matches an actual bottleneck, reply DEMO and I’ll send the run before we discuss an install.

DEMO CALL
1. Confirm one bottleneck in buyer's words.
2. Run the exact workflow, not a slide deck.
3. Show inputs, evidence, output, and scoreboard.
4. Show the human approval boundary and failure behavior.
5. Explain week-one deliverable.
6. Quote only the scope demonstrated or clearly specified.

FUNNEL
pain verified -> demo sent/viewed -> qualified install -> scope agreed -> agreement/payment verified -> workflow installed -> week-one acceptance -> recurring value measured

KILL
- no working demo
- “do my whole company” with no bounded first job
- fake proof/results requested
- prohibited access/credential sharing requested
- ads or non-approved spend required
- buyer demands guaranteed overnight revenue
- value cannot be measured or observed enough to support the proposed performance fee

DONE
One named workflow is installed, the promised week-one deliverable is accepted, the scoreboard reports evidenced operating events, and any payment attributed to the install is externally verified.
